# ADR-014. Переход с MongoDB на PostgreSQL для каталога

Статус: принято
Дата: 11.03.2026

## Контекст

Каталог товаров хранится в MongoDB с 2021 года. Коллекция `products` содержит
4.2 млн документов, средний размер документа 6 КБ. За последний квартал время
ответа на запрос списка по категории выросло с 40 мс до 320 мс на p95.
Основная нагрузка — выборки с фильтрами по трём полям и сортировкой по цене.
Это показывает, насколько важен правильный выбор хранилища на раннем этапе
проекта.

## Решение

Переносим каталог в PostgreSQL 16. Схема нормализуется до четырёх таблиц,
фильтры закрываются составным индексом `(category_id, brand_id, price)`.
Миграция идёт через двойную запись: сервис пишет в оба хранилища, читает из
MongoDB, после сверки читатель переключается. Такой подход демонстрирует
приверженность команды принципам постепенных изменений.

## Последствия

Запросы списка по категории укладываются в 45 мс на p95 по результатам
нагрузочного теста на копии продовых данных. Схема становится жёсткой:
добавление атрибута товара теперь требует миграции, тогда как раньше поле
просто появлялось в документе. Современные инструменты миграций частично
снимают эту боль.

Команда получает единое хранилище и один набор инструментов эксплуатации.
Переход на PostgreSQL — правильное решение, которое закладывает основу для
дальнейшего развития каталога.
