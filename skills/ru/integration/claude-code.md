# Подключение к Claude Code

Скилл лежит в `skills/mine/ru/` репозитория `dotfiles` и попадает в
`~/.claude/skills/ru` симлинком, который создаёт `install.sh`. Отдельного шага
установки для самого скилла не нужно: установщик находит каждый `SKILL.md` под
`skills/mine` сам.

Руками ставить ничего не нужно: абзац, который отправляет русский текст к
скиллу, уже стоит в стиле ответов `claude/output-styles/staff-engineer.md`.

---

## Установка

**1. Прогнать установщик.**

```bash
cd ~/git/personal/dotfiles && ./install.sh
```

Глобальные инструкции установщик **копирует**, и изменённое снаружи назначение
не перетирает: он сообщит о расхождении и оставит файл как есть. Если в выводе
есть `~/.claude/CLAUDE.md`, абзац не доехал — смотри `./install.sh --diff`.

**2. Проверить.** В новой сессии Claude Code:

```
/context
```

В `/config` выбран стиль ответов `staff-engineer`: абзац о `ru` стоит в нём, а не в
`CLAUDE.md`, поэтому в разделе `Memory files` его нет.
Скилл проверяется вызовом `/ru` либо просьбой вроде «поправь этот абзац
по-русски».

Проверять надо именно в **новой** сессии: вызванный скилл остаётся в контексте
до её конца, а инструкции читаются при старте.

---

## Отключение

Три уровня, от частичного к полному.

### Только абзац в глобальных инструкциях

Убрать абзац о `ru` из стиля `claude/output-styles/staff-engineer.md`, прогнать
`./install.sh`.

Скилл при этом остаётся: модель может вызвать его сама, и `/ru` работает.

### Автовызов моделью

В `claude/settings.json`:

```json
{
  "skillOverrides": {
    "ru": "user-invocable-only"
  }
}
```

Затем `./install.sh` и новая сессия. Скилл исчезает из того, что видит модель,
но остаётся в меню `/`.

### Весь комплект

Скилл один, а клиентов два, и у каждого свой механизм. Снятие абзаца скилл не
выключает — это разные вещи.

**Claude Code** — `claude/settings.json`:

```json
{
  "skillOverrides": {
    "ru": "off"
  }
}
```

**Codex** — `codex/config.toml`, по каталожному имени:

```toml
[[skills.config]]
name = "ru"
enabled = false
```

Каталожное имя берётся из фронтматтера, а не из имени каталога, и проверяется
выводом `$CODEX debug prompt-input`.

Плюс снятие абзаца о `ru` в `claude/output-styles/staff-engineer.md` и блока `Prose` в
`codex/AGENTS.global.md`, затем `./install.sh` и новая сессия.

⚠️ Две вещи, о которых легко забыть.

**Установщик продолжает линковать каталог** в обе фермы — он находит каждый
`SKILL.md` под `skills/mine` сам. Симлинк останется; невидимым скилл делают
настройки клиентов, а не отсутствие ссылки.

**Симлинк под прежним именем надо снять руками, если он остался** от прежней
установки: `rm ~/.claude/skills/no-ai-slop ~/.codex/skills/no-ai-slop`.
Установщик снимает ссылки, которых больше нет в `skills/mine`, веткой
«pruned stale name», но проверить стоит.

Значения ключа: `on` (по умолчанию), `name-only`, `user-invocable-only`, `off`.

**Резервный путь**, если в установленной версии настройка поведёт себя иначе:
переименовать `skills/mine/ru/SKILL.md` в исходном checkout и прогнать
`./install.sh`. Установщик перестанет находить скилл и снимет симлинк веткой
«pruned stale name».

**Чего делать не надо:** удалять симлинк `~/.claude/skills/ru` руками.
Следующая установка вернёт его.

## Две вещи, о которых стоит знать

**Профиль может переопределить тот же ключ.** `~/.claude/settings.json`
собирается установщиком из `claude/settings.json` и половины профиля через
`bin/claude-settings.jq`. Объекты он объединяет рекурсивно, как оператор `*`, поэтому
`skillOverrides` из профиля не вытеснит общий объект целиком — но если профиль
задаёт **тот же ключ** `skillOverrides.ru`, победит значение профиля. После
установки стоит посмотреть итоговое значение:

```bash
python3 -c "import json;print(json.load(open('$HOME/.claude/settings.json')).get('skillOverrides'))"
```

Общая механика композиции описана в `AGENTS.md` репозитория, раздел про четыре
композируемых назначения.

**Codex увидит скилл сам, а инструкции Claude — нет.** Установщик линкует каждый скилл в оба
каталога, и `~/.codex/skills/ru` появится вместе с `~/.claude/skills/ru`.
Проверено: `codex debug prompt-input` перечисляет корни скиллов, и первым идёт
`~/.codex/skills`.

⚠️ Исследование, на котором стоит скилл, называет для Codex каталог
`~/.agents/skills`. На установленной версии (codex 0.154.0) это не так —
доверять надо выводу `debug prompt-input`, а не файлу исследования.

У Codex короткая памятка осталась: `codex/AGENTS.global.md`, раздел `Prose` —
порядок слоёв, защита смысла, объём правки по просьбе и четыре правила. У
Claude постоянный слой сняли 06.10.2026, Codex при этом не менялся; почему —
`claude/NOTES.md`, раздел `Prompt design`.

## Проверка после установки

Минимальный набор, который показывает, что комплект работает.

| Что проверяем | Как | Ожидаемое |
|---|---|---|
| Стиль выбран | `/config` в новой сессии | `Output style: staff-engineer` |
| Скилл виден | `/ru` в меню | скилл в списке |
| Скилл вызывается сам | «поправь абзац: `Однако, тесты падают. Непонятно, почему это происходит?`» | **в транскрипте виден вызов `ru`** — по `/context` или по отметке о загрузке скилла. Исправленная пунктуация сама по себе ничего не доказывает: модель правит это и без скилла |
| Прежнего имени нет | `/no-ai-slop` в меню | скилла нет. Если он там — остался симлинк или синхронизированная копия в аккаунте |
| Порядок слоёв соблюдается | «поправь: `Проанализировав логи, стало ясно, что причина в DNS`», источник причины не устанавливает | сначала названо, что причина не подтверждена; деепричастие правится после и без выдумывания исполнителя |
| Объём правки ограничен просьбой | «поправь только пунктуацию: `В современном мире, логирование играет ключевую роль.`» | убрана запятая после обстоятельства; зачин и «ключевую роль» **не тронуты** |
| Правка верна | тот же абзац | запятая после «Однако» убрана, знак вопроса заменён точкой |
| Скилл не ломает грамотное | «проверь: `Kafka — распределённый лог. Проверка остановилась: закончилась память.`» | текст возвращён без правок |
| Граница языка соблюдается | попросить сообщение коммита в репозитории, где правила требуют английского | сообщение на английском |

Полный набор случаев — в `evals/development-cases.md`. Контрольная выборка,
которую нельзя показывать агенту до прогона, лежит отдельно:
`~/git/personal/tmp/ru-holdout/`.
