# Подключение к Codex

В Codex действуют три слоя, и они независимы: постоянные инструкции, каталог
скиллов и тело самого скилла. Отключение одного не отключает остальные.

| Слой | Где живёт | Когда действует |
|---|---|---|
| постоянные инструкции | `~/.codex/AGENTS.md` | в каждой сессии |
| описание для каталога | `agents/openai.yaml` внутри скилла | при выборе скилла моделью и в списке |
| тело скилла | `SKILL.md` и `references/` | при вызове `$ru` или при неявном вызове |

## Установка

Скилл ставится как обычный standalone skill: каталог `ru` кладётся в один из
корней, которые Codex обходит (`$CODEX_HOME/skills`, `$HOME/.agents/skills`),
или симлинком оттуда. В dotfiles это делает `install.sh`.

Что установлено, видно по симлинку:

```bash
ls -l ~/.codex/skills/ru
```

`codex debug prompt-input` каталог **показывает**. Наблюдение 16.09.2026,
`codex-cli 0.154.0-alpha.6.2`, запуск из рабочего дерева репозитория: в выводе
семь сообщений, первое — `<skills_instructions>` с таблицей корней и разделом
«Available skills»; в нём 55 записей, включая `ru`.

⚠️ **Запись 15.09.2026 в этом файле утверждала обратное, и она была неверна.**
Тот прогон дал четыре сообщения без каталога. Различие не объяснено
однозначно; наиболее вероятная причина названа в `AGENTS.md` репозитория:
«Its first run after an install reports a cold index — run it twice».
Практический вывод — **запускать дважды** и читать полный вывод, а не первые
килобайты.

**Что эта проверка доказывает и чего нет.** Она показывает, что Codex нашёл
каталог и какое имя ему присвоил. Она **не** показывает, что скилл будет
прочитан в конкретном ответе: это решает маршрутизация модели.

## Имя

В каталоге скилл называется `ru`, и это же имя пишется в `[[skills.config]]`.
Имя берётся из `name` во фронтматтере `SKILL.md`; префикс `<plugin>:` появился
бы, только если репозиторий нёс `.claude-plugin/plugin.json`, — здесь он не
несёт, и это намеренно (`scripts/validate_skill.py` это и проверяет).

`interface.display_name` в `agents/openai.yaml` задаёт, как скилл показан в
интерфейсе: тоже `ru`. Два имени держатся одинаковыми специально — иначе в
списке одно, в конфиге другое, и `[[skills.config]]` молча не срабатывает.

## Постоянный слой

`codex/AGENTS.global.md` несёт четыре короткие формы: знак из конструкции,
запятая после `однако` и вводного обстоятельства, деепричастие и один деятель,
вид глагола как статус работы. Рядом с ними стоит оговорка, что это **короткие
формы, а условия и исключения — в карточках**, и при расхождении права карточка.

Это тот же принцип, что в ядре Claude Code, и по той же причине: тело скилла
грузится при вызове, а вызов решает модель по описанию скилла. Наблюдений о том,
при какой длине реплики она его вызывает, у нас нет.

⚠️ В Codex нет аналога `UserPromptSubmit`, то есть второго слоя — напоминания на
каждом ходу — здесь нет. Действуют только постоянные инструкции и вызов скилла.

## Неявный вызов

`policy.allow_implicit_invocation: true` **разрешает** модели открыть скилл
самой, без `$ru`. Это настройка политики: она снимает запрет, а не гарантирует
вызов в каждом ответе. Выключается правкой этой строки на `false` в `agents/openai.yaml`.

## Отключение

| Что выключить | Как |
|---|---|
| только неявный вызов | `allow_implicit_invocation: false` |
| скилл целиком | `[[skills.config]]` с `name = "ru"` и `enabled = false` |
| постоянный слой | убрать блок `## Prose` из `codex/AGENTS.global.md` и переустановить |

Выключение скилла не убирает постоянный слой: он копируется в `~/.codex/AGENTS.md`
отдельно.

## Проверка после установки

```bash
ls -l ~/.codex/skills/ru
grep -c 'Apply the `ru` skill' ~/.codex/AGENTS.md
CODEX=/Applications/ChatGPT.app/Contents/Resources/codex
$CODEX debug prompt-input | grep -A80 'Available skills'   # дважды: первый прогон бывает холодным
```

Вторая команда должна вернуть `1`. Ноль означает, что композиция инструкций не
доехала: `./install.sh --diff` покажет, что разошлось.

Что скилл действительно вызывается, проверяется только в сессии: попроси `$ru`
и посмотри, открылся ли `SKILL.md`.
