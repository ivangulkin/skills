# Duo Gemini to Codex: парный разбор с Codex

Codex — оппонент. Один чат Gemini / Antigravity ведёт **один постоянный тред** в Codex Desktop: сначала вы можете согласовать замысел (`--phase design`), а после реализации — проверить код в том же треде (`--phase review`), где у Codex в контексте остаются его собственные прежние возражения `p0`/`p1`. Ревью без предварительной фазы дизайна тоже работает — тред просто создаётся на первом вызове.

В самом Codex этот скилл выключен в `codex/config.toml` (для обратного направления из Codex в Gemini используется `duo-codex-to-gemini`).

```bash
# путь, а не команда: zsh не разбивает переменную на слова, и "python3 …"
# одной строкой превратился бы в имя несуществующей программы
DUO="$HOME/.codex/skills/duo-gemini-to-codex/scripts/duo"
python3 "$DUO" verify      # ничего не тратит; всё, что можно проверить до первого токена
```

## Выбор фазы

Фаза передаётся флагом `--phase` под капотом в зависимости от запроса человека:

| Запрос человека | Фаза | Что делает оппонент |
|---|---|---|
| «составь дизайн», «спланируй изменения», «согласуй план», «договоритесь» | `--phase design` | Ищет, что в замысле не учтено, где предположение выдано за факт, что развалится на границах |
| «проведи ревью», «отдай на ревью», «проверь сделанное» | `--phase review` | Проверяет реализацию против задачи и собственных прежних `p0`/`p1` в том же треде |

## Шаги раунда

1. **Подготовь бриф.** Напиши сообщение по шаблону [`brief-template.md`](references/brief-template.md) в файл `$TMPDIR/duo-<phase>-<n>.md` во временном каталоге сессии, а не в репозитории:
   - Для `design`: заполни все шесть разделов, укажи файлы путями (не вставляй простыни кода), в разделе «где не уверен» сформулируй хотя бы один настоящий вопрос.
   - Для `review`: укажи ветку, диапазон коммитов и команду для получения `git diff` (вставлять diff целиком можно только если он короче экрана; Codex сам читает репозиторий), а в разделе 6 — границы проверки.

2. **Запусти раунд.** Ход идёт минутами, запускай с явным `--request-id`:

   ```bash
   RID=$(uuidgen | tr A-Z a-z)   # запомни: он нужен для повтора и для подтверждения
   python3 "$DUO" ask --phase design --message-file "$TMPDIR/duo-design-1.md" --model '5.6 luna light' --request-id "$RID"
   ```

   Для ревью большой ветки бери модель сильнее (`--model 'astra max'` или профиль `default`) и при необходимости поднимай `--context-window`: пропущенный дефект дороже квоты.
   Если вывод потерян или ход прерван — повтори команду с **тем же** `--request-id`: ответ воспроизведётся или дособерётся из истории, второй ход не уйдёт.

3. **Разбери возражения по `id`.** Когда в выводе строка `ПРОДОЛЖАТЬ:`, каждое блокирующее возражение (`p0`/`p1`) требует ответа в разделе 5 следующего брифа:
   - На фазе `design`: `принято` (что изменилось в плане), `отклоняю` (с доказательством по коду или фактам) либо `снято`.
   - На фазе `review`: либо исправление в коде отдельным коммитом и `принято` со ссылкой на коммит, либо `отклоняю` с доказательством. Вердикт никогда не принимается пакетом: у моделей-ревьюеров придирки и выдуманные баги идут вперемешку с настоящими.
   Следующий вызов запускай с `--ack-request-id "$RID"` и новым `--request-id`. Возвращайся к шагу 2.

4. **Остановись на человека.** Когда вывод сказал `ИТОГ:`, покажи человеку картину целиком:
   - На фазе `design`: итоговый план, что Codex принял, что осталось спорным, и обе позиции по каждому спорному пункту без выбора за человека. Работа начинается только после подтверждения человека.
   - На фазе `review`: что исправлено, что подтверждено и что осталось спорным с обеими позициями.

5. **Покажи тред.** Только после завершения фазы и ответа человеку дай строку `смотреть: open "codex://threads/<id>"` из вывода. Раньше открывать тред в Desktop не нужно: открытый тред держит writer-лок, и на следующем раунде `duo` придётся делать `thread/fork`.

## Как выглядит ответ

По умолчанию — `--verdict-format trailer`, и переключать его на `json` не нужно:
Codex всегда отвечает сначала понятной человеку прозой (которую человек читает в
окне Desktop), а в самом конце прикладывает один блок ```json с вердиктом (для
робота). Формат `json` оставляет только голый JSON без прозы и в Desktop
нечитаем — в обычных раундах его не используй.

Вердикт: `stance` (`agree` / `disagree` / `needs_info`), `stop`, `confidence`,
`summary`, `findings[]` с `id`, `severity` `p0`–`p3`, `claim`, `evidence`,
`response` (`new` / `confirm` / `dispute` / `retract`), `rationale`, и
`open_questions[]`. Возражение с `!` в выводе держит цикл: `p0`/`p1` в
состоянии `new` или `dispute`.

## Правило остановки

Потолок `--max-rounds` (3), досрочный выход только после `--stop-hold` (2)
согласных раундов подряд. Итоги:

| `ИТОГ:` | Что значит |
|---|---|
| `converged` | согласие продержалось два раунда |
| `agreed_unheld` | последний раунд чистый, но два подряд не набралось |
| `stable_disagreement` | те же блокирующие возражения два раунда подряд, либо потолок с открытыми |
| `needs_info` | потолок, Codex ждёт ответов на `open_questions` |
| `max_rounds` | потолок без согласия и без открытых блокеров |
| `unparseable` | Codex не дал разбираемый вердикт до конца |

Согласие двух моделей — рекомендация. Решение и запуск — за человеком.

## Почему протокол устроен именно так

Обмен репликами сам по себе ответ не улучшает — это измерено, и предпосылки
скилла из этого и растут. Разбор литературы 05.09.2026 лежит в
[`references/why-this-protocol.md`](references/why-this-protocol.md), коротко —
четыре вещи.

Схождение к согласию не доказывает правоту: среди агентов, меняющих ответ,
переходы «правильно → неправильно» встречаются чаще обратных. Отсюда
`--stop-hold 2` и формулировка выше: `converged` — это не «мержим», а материал
для решения человека.

Смена позиции требует основания, не давления. Инцентивная формулировка вроде
«будь точным» не помогает и иногда вредит; помогает процедурная — «меняй
позицию, только если можешь назвать конкретную причину». Она стоит в
`developerInstructions` и продублирована в контракте вердикта, а правило
остановки её обеспечивает: прежнее p0/p1 закрывается только по своему id
ответом `confirm` или `retract` с непустым `rationale`. Id, пропавший из
вердикта, и голый `retract` блокер не закрывают — раунд не считается согласным,
и строка `ПРОДОЛЖАТЬ:` называет незакрытые id.

Вердикт критика зашумлён. Галлюцинированные баги и придирки модель выдаёт чаще
человека, а на фронтире точность одиночного ревью измеряется единицами
процентов. Поэтому вердикт разбирается по находкам: каждое `p0`/`p1` — либо
исправление, либо отклонение с доказательством, и пакетом он не принимается
никогда.

Спор дороже голосования и без вмешательств проигрывает ему. Ценность здесь не в
самом факте второй модели, а в том, что разбор идёт по перечислимым находкам с
доказательствами и стабильными id.

## Модель, усилие, скорость, контекст

```bash
python3 "$DUO" models                                    # каталог установленного Codex
--model '5.6 luna light'   --model 'sol max'      # разговорное имя или слаг
--effort ultra                                    # перекрывает и алиас, и профиль
--service-tier-for-turn priority                  # быстрее, тратит больше; default — стандарт
--context-window 200000  --auto-compact-limit 150000
--profile test                                    # gpt-5.6-luna / low; default — gpt-6-astra / max
```

Усилие, которого нет в каталоге для модели, даёт предупреждение, а не отказ.

Аргумент вызова скилла — подсказка, какие из этих флагов выставить: «luna light»
означает `--model '5.6 luna light'`. Без подсказки — профиль `default`.

## Запросы: `--request-id` и `--ack-request-id`

У каждого раунда есть id, который **даёт вызывающая сторона** и хранит у себя:

```bash
RID=$(uuidgen | tr A-Z a-z)
python3 "$DUO" ask --phase design --message-file "$TMPDIR/b1.md" --request-id "$RID"
# следующий раунд — подтвердить прошлый и дать новый id
python3 "$DUO" ask --phase design --message-file "$TMPDIR/b2.md" \
  --ack-request-id "$RID" --request-id "$(uuidgen | tr A-Z a-z)"
```

Зачем это нужно, в трёх сценариях, каждый воспроизведён тестом:

- **Ответ потерян** (процесс убит после записи результата, до вывода): тот же
  `--request-id` **воспроизводит** сохранённый ответ; второй ход не создаётся.
- **Ход прерван** (тишина, `Ctrl-C`, падение): тот же id находит ход в истории
  треда по `clientUserMessageId` и забирает результат, не отправляя бриф
  повторно.
- **Id потерян** (сессия перезапустилась): любой другой id получает отказ
  с кодом 7 и распечатку сохранённого ответа; ход не создаётся. Дальше —
  `duo ack <старый id>` либо `--ack-request-id`.

Без `--request-id` он генерируется и печатается; но повторить такой раунд после
сбоя уже нельзя. Передавай `--request-id` всегда.

## Состояние: где живёт связь и как разрешаются субагенты

Файл `~/.gemini/state/duo/<ключ>.json`. Ключ — `ANTIGRAVITY_CONVERSATION_ID`
текущего чата. Если `duo` вызван из субагента Antigravity, скрипт проходит по
цепочке `parent_conversation_id` в базе
`$ANTIGRAVITY_APP_DATA_DIR/conversation_summaries.db` до корневого чата, чтобы
субагент продолжал тот же тред Codex, что и родительская сессия.

На всё время команды держится `flock` на ключе — второй запуск получает отказ
с кодом 8, а не второй тред. Битый файл уходит в карантин с durable-маркером:
следующий запуск **блокируется** (код 9), а не создаёт новый тред; снимают
блок только `--new` или `recover`.

## Где тред окажется в Codex Desktop, и как он называется

Каталог треда — корневой каталог рабочего пространства чата Antigravity из
`workspace_uris` в `conversation_summaries.db`, а не текущий `$PWD` в момент
вызова. `--cwd` перебивает всё.

Имя треда следует за заголовком чата (`title` из `conversation_summaries.db`):
каждый настоящий раунд отправляет актуальный заголовок. `--name` закрепляет
имя; `--name-from-chat` снимает закрепление.

## Остальные флаги `ask`

`--phase design|review` (обязателен), `--message-file` или `--message`, `--new`
(старый тред уходит в архив; `--keep-old` оставляет), `--name`, `--session`,
`--idle-timeout` (900 с **тишины**), `--timeout` (жёсткий потолок, по умолчанию
нет), `--no-fork` (не форкать тред, который держит Desktop), `--max-message-chars`
(120 000), `--reveal`, `--json`, `--dry-run`.

Песочница треда — `--sandbox read-only|workspace-write|danger-full-access`; без
флага действует конфигурация Codex.

## Другие команды

```bash
python3 "$DUO" status           # тред этой сессии, модель последнего раунда, фазы
python3 "$DUO" schema           # схема вердикта
python3 "$DUO" close            # забыть связь сессии с тредом
python3 "$DUO" close --archive  # и заархивировать тред
python3 "$DUO" ack <request-id>  # подтвердить раунд, не начиная следующий
python3 "$DUO" recover --from <старый ключ>   # перенести связь под текущий ключ
python3 "$DUO" repair-redirect <ключ>        # убрать в сторону нечитаемый редирект
python3 "$DUO" repair-redirect <ключ> --to <ключ>   # или переписать его
```

## Что может пойти не так

| Симптом | Причина | Что делать |
|---|---|---|
| `forked it into …` в stderr | тред открыт в Codex Desktop, и Desktop держит writer-лок до своего перезапуска | ничего: `duo` сам сделал `thread/fork` — новый тред со всей историей. Исходный сразу переименован в `[старый] …` и будет заархивирован, как только Desktop его отпустит |
| `quota is exhausted` | лимит Codex | подождать, либо `--profile test` |
| `no longer fits the model's context window` | тред перерос окно | `--new`, либо `--context-window` больше |
| `the message is N characters` | вставлен diff | указать путь вместо содержимого |
| `no longer exists` | тред удалён в Desktop | `--new` |
| код 7, `request … is still running` / `not acknowledged` | прошлый раунд не подтверждён | `--request-id <тот же>` — повторить/дождаться; `--ack-request-id <тот же>` + новый id — идти дальше |
| код 8, `in use by another duo process` | второй запуск на ту же сессию | дождаться первого; `duo status` |
| код 9, `blocked after quarantine` | state-файл был повреждён и отправлен в карантин | `--new` либо `duo recover --from`; `close` маркер **не** снимает, только `close --force` |
| код 10, `still running after waiting` | ход ещё идёт на сервере, мы дождались лимита ожидания | ничего не прервано; повторить позже с тем же `--request-id` |
| `no message from Codex for Ns` | Codex молчал дольше `--idle-timeout`; ход прерван, сообщение уже в треде | короткое «продолжи с того места», а не повтор брифа — повтор даст дубликат хода |
| `unparseable` | в конце ответа пропущен блок ````json` | в следующем раунде попросить повторить вывод с блоком ````json` внизу (не переключаясь на `--verdict-format json`, чтобы в треде оставалась человеческая проза) |
| треда нет в sidebar | Desktop не перечитал список | после последнего раунда — `open "codex://threads/<id>"` |

## Границы

- Codex читает репозиторий и запускает тесты с теми же правами, что в вашем
  Desktop («Approve for me» на этом ноутбуке); файлы не меняет — это правило
  в его инструкциях, не песочница. Ужать можно флагом `--sandbox read-only`.
- Один чат Gemini / Antigravity — один тред Codex. Новый тред только по `--new`:
  прежний уходит в архив (`--keep-old` оставляет), а память о договорённостях
  с ним теряется.
