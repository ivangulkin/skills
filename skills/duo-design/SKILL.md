# Согласовать план с Codex

Codex — оппонент. Ты предлагаешь план, он ищет, что сломается, ты отвечаешь по
каждому возражению. Итог — согласованный план либо зафиксированное расхождение,
и оба уходят человеку на подтверждение. Работа начинается после его «да».

Движок, флаги и параметры раунда — в скилле `duo`. Прочитай
`~/.claude/skills/duo/SKILL.md` до первого раунда и снова после сжатия
контекста: этот файл читается не как скилл, и после сжатия его в контексте
может не остаться.

## Шаги

1. **Бриф.** Напиши сообщение по [`brief-template.md`](../duo/references/brief-template.md)
   в файл `duo-design-<n>.md` во временном каталоге сессии — том, который среда
   отводит под черновики, а не в репозитории. Готово, когда заполнены все шесть разделов,
   файлы указаны путями, а не вставлены, и в разделе «где не уверен» стоит
   хотя бы один настоящий вопрос.

2. **Раунд.** Запусти его фоновой задачей — ход идёт минутами:

   ```bash
   RID=$(uuidgen | tr A-Z a-z)   # запомни: он нужен для повтора и для подтверждения
   python3 "$HOME/.claude/skills/duo/scripts/duo" ask --phase design --message-file "$TMPDIR/duo-design-1.md" --model '5.6 luna light' --request-id "$RID"
   ```

   Готово, когда в выводе есть строка `ПРОДОЛЖАТЬ:` или `ИТОГ:`. Если вывод
   потерян или ход прерван — повтори команду с **тем же** `--request-id`: ответ
   воспроизведётся или дособерётся из истории, второй ход не уйдёт. Первый вызов
   создаёт тред с именем текущего чата; следующие идут в него же.

3. **Ответ по id.** Для каждого возражения из вывода — в следующий бриф, раздел
   5: `принято` с тем, что изменилось в плане, `отклоняю` с доказательством,
   либо `снято`. Готово, когда ни одно возражение `p0`/`p1` не осталось без
   ответа. Следующий вызов — с `--ack-request-id "$RID"` и новым `--request-id`.
   Возвращайся к шагу 2.

4. **Остановка на человека.** Когда вывод сказал `ИТОГ:`, покажи человеку
   итог целиком: план, что Codex принял, что осталось спорным, и обе позиции
   по каждому спорному пункту — своими словами каждой стороны, без выбора за
   него. Готово, когда человек подтвердил план или изменил его.

   `converged` — рекомендация двух моделей, не разрешение. `agreed_unheld` —
   сошлись на последнем раунде, но согласие не продержалось два раунда; человек
   решает, добавить ли `--max-rounds 4`. `stable_disagreement` — показывать как
   расхождение, не сглаживать.

5. **Показать тред.** После подтверждения — и только после — дай человеку
   строку `смотреть: open "codex://threads/<id>"` из вывода. Раньше нельзя:
   открытый в Desktop тред блокирует следующий раунд.

## Границы

- Codex читает репозиторий и запускает тесты с теми же правами, что в вашем
  Desktop («Approve for me» на этом ноутбуке); файлы не меняет — это правило
  в его инструкциях, не песочница. Ужать можно флагом `--sandbox read-only`.
- Один чат Claude — один тред Codex. Новый тред только по `--new`: прежний
  уходит в архив (`--keep-old` оставляет), а память о договорённостях с ним
  теряется.
- Ревью сделанной по этому плану работы — скилл `duo-review`, тот же тред.
