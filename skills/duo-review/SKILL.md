# Ревью сделанного с Codex

Тот же тред, что и при согласовании плана: прежние возражения у Codex в
контексте, и он проверяет работу против **собственных** p0/p1, а не с чистого
листа. Ревью без предыдущей фазы тоже работает — тред просто создаётся здесь.

Движок и все флаги — в скилле `duo`; здесь только шаги этой фазы.

```bash
# путь, а не команда: zsh не разбивает переменную на слова, и "python3 …"
# одной строкой превратился бы в имя несуществующей программы
DUO="$HOME/git/personal/dotfiles/skills/mine/duo/scripts/duo"
```

## Параметры раунда

Те же, что у `duo-design`: `--model`, `--effort`, `--service-tier-for-turn`,
`--context-window`, `--auto-compact-limit`. Аргумент скилла — подсказка, какие
выставить. Ревью большой ветки — повод для `--context-window` побольше и модели
посильнее: пропущенный дефект дороже квоты.

## Шаги

1. **Собрать материал.** Что сделано и где это лежит: ветка, диапазон коммитов,
   команда для diff. В бриф по [`brief-template.md`](../duo/references/brief-template.md)
   идёт указатель, а не сам diff — Codex читает репозиторий. Вставлять diff
   целиком можно, когда он короче экрана. Раздел 6 брифа — что проверять
   именно сейчас: корректность, безопасность, соответствие плану. Готово, когда
   в брифе есть способ *получить* изменения и граница проверки.

2. **Раунд.** Фоновой задачей:

   ```bash
   RID=$(uuidgen | tr A-Z a-z)   # запомни: он нужен для повтора и для подтверждения
   python3 "$DUO" ask --phase review --message-file "$TMPDIR/duo-review-1.md" --model 'astra max' --request-id "$RID"
   ```

   Бриф лежит во временном каталоге сессии, не в репозитории.

   Готово, когда в выводе есть `ПРОДОЛЖАТЬ:` или `ИТОГ:`.

3. **Исправить или отклонить.** Каждое `p0`/`p1` из вывода — либо исправление
   в коде и `принято` в разделе 5 следующего брифа с указанием коммита, либо
   `отклоняю` с доказательством. Вердикт разбирается по находкам и никогда не
   принимается пакетом: у моделей-ревьюеров измеренная точность одиночного
   ревью — единицы процентов, придирки и выдуманные баги идут вперемешку с
   настоящим. Отклонение по факту — нормальный исход, если факт проверен.
   Готово, когда ни одно блокирующее возражение не осталось без ответа. Следующий вызов — с `--ack-request-id "$RID"` и новым `--request-id`.
   Возвращайся к шагу 2.

4. **Итог человеку.** Когда вывод сказал `ИТОГ:` — список того, что исправлено,
   что осталось спорным с обеими позициями, и что Codex подтвердил. `converged`
   и `agreed_unheld` — не сигнал мержить, а материал для решения человека.
   Готово, когда человек принял решение.

5. **Показать тред.** После итога дай строку `смотреть: open "codex://threads/<id>"`.
   Раньше нельзя: открытый в Desktop тред блокирует следующий раунд.

## Границы

- Codex только читает; исправления делаешь ты, и каждое — отдельным коммитом,
  на который можно сослаться в разделе 5.
- Прошлые возражения Codex поднимет снова под теми же `id`, если сочтёт, что
  они обойдены, а не закрыты. Это и есть смысл общего треда.
