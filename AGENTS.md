# skills

Публичный репозиторий скиллов для Claude Code и Codex. Для пользователей —
[README.md](README.md); здесь то, что нужно тому, кто пишет или меняет скиллы.
Скилл со своими правилами несёт собственный `AGENTS.md`, и он старше этого.

## Раскладка

- Скилл лежит в `skills/<имя>/` и самодостаточен: установка копирует или линкует
  только этот каталог, поэтому ссылки внутри него не выходят за его границы.
- Что ставится плагином Claude Code, описывает `.claude-plugin/marketplace.json`.
  Запись добавляется, когда скилл готов; недоделанный остаётся вне marketplace.
- `.claude-plugin/plugin.json` не создаётся ни в корне, ни в скилле. Если он
  есть, Codex добавляет к каталожному имени скилла префикс `<плагин>:`, и запись
  `name = "ru"` в `[[skills.config]]` перестаёт срабатывать.
- Репозиторий публичный. Токенам, паролям, ключам API, рабочим хостам, ключам
  задач и именам коллег в нём не место ни в каком виде.

## Новый скилл

1. Каталог `skills/<имя>/` с `SKILL.md`.
2. Для Codex — `agents/openai.yaml`.
3. Проверка, которая падает, когда логика ломается: тесты рядом со скиллом и
   команда запуска в его `README.md` или `AGENTS.md`. Скилл без кода проверяется
   вызовом на двух-трёх запросах, один из которых скилл не должен обрабатывать.
4. Запись в `marketplace.json`, когда скилл готов:

   ```json
   {
     "name": "<имя>",
     "source": "./",
     "description": "<одна фраза>",
     "strict": false,
     "skills": ["./skills/<имя>"]
   }
   ```

5. Строка в таблице `README.md`.

CI в репозитории нет: проверки запускаются локально перед коммитом.

## SKILL.md

Модель выбирает скилл по `description`, а тело читает только после выбора. Из
этого следует остальное.

**`name`** совпадает с именем каталога: строчные латинские буквы, цифры и
дефисы, до 64 знаков.

**`description`** до 1024 знаков и отвечает на три вопроса: что скилл делает,
по каким просьбам его вызывать, к чему он не применяется. Граница важнее
перечня: расплывчатое описание вызывает скилл там, где он не нужен.

**Тело** — процедура и маршрут к справочникам, а не сами справочники. Объёмное
выносится в `references/`, и `SKILL.md` называет, когда какой файл открывать.
Модель читает файл, когда он нужен, и не тратит контекст на остальные.

**Правило пишется вместе с условием.** Короткое правило без условия ломает
грамотный результат: агент применяет его там, где оно не работает. К правилу, от
которого легко ошибиться, добавляются случай срабатывания, случай
несрабатывания и граница между ними.

**Одно правило живёт в одном месте.** Вторая формулировка в другом файле
расходится с первой, и непонятно, какая из них верна.

**Инструкция — действие и условие**, а не описание. «Открой карточку, если в
тексте есть тире» работает, «тире бывает разным» — нет.

**Личного в тексте нет.** Скилл ставят чужие люди: пути к каталогам автора и
названия его проектов в тексте скилла не нужны.

## Claude Code

- Читает `~/.claude/skills/<имя>/SKILL.md` и скиллы поставленных плагинов.
  Поставленный плагином скилл вызывается как `/<плагин>:<скилл>`, скопированный
  в `~/.claude/skills` — как `/<скилл>`.
- Ключи frontmatter, которые читает только Claude Code:
  `disable-model-invocation: true` (скилл вызывается только вручную) и
  `argument-hint`. Автовызов настраивает пользователь в `skillOverrides` файла `settings.json`:
  `on`, `name-only`, `user-invocable-only`, `off`.
- Новая версия скилла видна в новой сессии: вызванный скилл остаётся в контексте
  до её конца.
- Проверка манифеста и скиллов: `claude plugin validate .`.

## Codex

- Обходит `$CODEX_HOME/skills` и `$HOME/.agents/skills`. Вызывается как `$имя`.
- Имя в каталоге берётся из `name` во frontmatter, не из имени каталога.
  `[[skills.config]]` в `config.toml` сопоставляется именно с ним.
- `agents/openai.yaml` задаёт показ и политику:

  ```yaml
  interface:
    display_name: "<имя>"        # то же, что name во frontmatter
    short_description: "<короткая фраза для списка>"
    default_prompt: "Используй $<имя> для …"
  policy:
    allow_implicit_invocation: true   # false — только по явному $имя
  ```

  `display_name` и `name` держатся одинаковыми: иначе в списке одно имя, в
  конфиге другое, и `[[skills.config]]` молча не срабатывает.
- Проверка каталога: `codex debug prompt-input`. Первый запуск бывает с
  холодным индексом, поэтому запускай дважды и читай вывод целиком. Он
  показывает, что скилл найден и под каким именем, но не что модель его
  прочитает в ответе.

## Коммиты

Английский, одна строка в повелительном наклонении без точки в конце, в тоне
`git log`. Тело — только если заголовок не вмещает причину.
